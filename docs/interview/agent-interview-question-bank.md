# Agent 应用开发面试问题清单

本问题清单仅根据 `docs/design/15-resume-project-description.md` 中的简历内容整理。

从大厂 Agent 应用开发岗位的面试视角看，这份简历会把面试重点集中在以下方向。

## 一、项目真实性与个人贡献

这是最先被验证的部分，因为简历使用了“从零设计”“项目作者 / 核心开发者”等强表述。

可能的问题：

1. 用 2 分钟介绍这个项目，重点说明解决了什么问题。
2. 这个项目是个人项目还是团队项目？你实际负责哪些模块？
3. 哪些部分是你独立设计的，哪些参考了已有 Agent 框架？
4. 项目大概有多少代码、测试和核心模块？
5. 你认为技术难度最高的三个问题是什么？
6. 哪个设计后来被证明是错误的？你是怎么重构的？
7. 如果只能保留三个核心能力，你会保留什么？
8. 为什么不直接使用 LangChain、LangGraph、AutoGen 或其他框架？
9. 你所说的“轻量级”具体体现在哪里？
10. 这个项目目前更偏教学、研究还是生产应用？生产化还缺什么？

高压追问：

- 如果去掉 Provider Adapter、Memory、Workflow，最小可运行内核是什么？
- 请现场画出一次完整任务从输入到结束的调用链。
- 项目的技术亮点中，哪一个是你真正原创的？

## 二、Agent Runtime 与核心循环

“基于生成器的显式 Agent 循环”是整份简历最容易被深挖的架构点。

可能的问题：

1. Agent Loop 的核心状态机是什么？
2. 为什么使用生成器，而不是普通循环、异步队列或者事件总线？
3. 生成器在这里解决了什么问题？
4. 一轮 Agent Turn 的输入、输出分别是什么？
5. `Message`、`Event`、`State` 分别承担什么职责？
6. 为什么同时需要 Message 和 Event？二者的边界是什么？
7. State 是可变对象还是不可变快照？
8. 工具调用结果如何重新进入模型上下文？
9. 如何识别模型已经完成任务？
10. 有哪些停止条件？
11. 如何防止 Agent 无限循环？
12. 如何处理模型只输出文本、不调用工具的情况？
13. 如何处理模型连续调用无效工具的情况？
14. Agent 执行中断之后能否恢复？恢复点是什么？
15. 同一个任务重放时是否能得到一致结果？
16. 如何处理流式模型输出和工具调用？
17. 为什么说这个运行机制是“显式”的？
18. 如果让我只看一个核心函数理解整个系统，它应该做什么？

高压追问：

- 请写出 Agent Loop 的伪代码。
- 模型返回两个工具调用时，State 在什么时刻更新？
- 工具执行成功，但结果尚未写入历史时进程崩溃，会发生什么？
- Event 是事实记录、控制命令，还是二者兼有？为什么？

## 三、Provider Adapter 与多模型兼容

简历明确声称支持 OpenAI Chat、Responses、Anthropic Messages 和 OpenAI-compatible 服务，因此会被检查是否真正理解各供应商协议差异。

可能的问题：

1. Provider Adapter 的统一接口是什么？
2. 为什么不能直接在 Runtime 中使用供应商返回对象？
3. 不同 Provider 的消息格式有哪些主要差异？
4. Tool Call ID 如何统一管理？
5. OpenAI Responses API 和 Chat Completions 的抽象差异是什么？
6. Anthropic 的 Tool Use 与 OpenAI Tool Call 如何映射？
7. System Prompt、工具定义和多模态内容如何统一表达？
8. Streaming Event 如何映射成项目自有事件？
9. Token Usage 和成本统计由哪一层负责？
10. Provider 不返回 Token Usage 时怎么办？
11. OpenAI-compatible 服务并不完全兼容时怎么处理？
12. 如何区分 Provider 通用能力和供应商特有能力？
13. 如果某个模型不支持并行工具调用，Runtime 怎么降级？
14. Provider Adapter 是否会成为“最低公共能力”抽象？
15. 新接入一个 Provider，需要修改哪些地方？

重点考察的是：你是否真正隔离了供应商差异，还是只用大量条件分支完成适配。

## 四、长上下文与 Context Engineering

这是简历中信息密度最高的部分，也是 Agent 岗位最核心的面试方向之一。

可能的问题：

1. 完整历史、活跃上下文、单轮模型输入分别是什么？
2. 为什么要划分这三层？
3. 完整历史是否始终保留？存储成本怎么控制？
4. 什么条件会触发上下文压缩？
5. 压缩按照 Token 数、消息数还是任务阶段触发？
6. 工具结果压缩与模型摘要有什么区别？
7. 如何避免摘要丢失关键事实？
8. 摘要错误会不会持续污染后续任务？
9. 如何保留压缩前的原始证据？
10. Recall 如何定位已经退出活跃上下文的信息？
11. Recall 是关键词检索、向量检索还是结构化索引？
12. Recall 结果如何防止再次把上下文撑爆？
13. Agent 主动 Compact 和系统自动 Compact 有什么区别？
14. 如何决定哪些消息必须保留？
15. 工具错误、用户约束和任务计划是否可以被压缩？
16. 上下文管理如何处理超大 Bash 输出或代码文件？
17. Token 预算如何在系统提示、历史、工具结果和输出之间分配？
18. 如何衡量压缩策略是否有效？
19. 如何测试压缩前后 Agent 行为没有明显退化？
20. 长周期任务失败通常是上下文不足，还是规划能力不足？

典型场景题：

## 十二、最需要提前准备的压力点

按面试风险排序，建议重点准备：

1. **评测数字的完整口径**
   模型版本、任务数量、预算定义、运行次数、Baseline 配置、成本与耗时。

2. **ProgramBench 与 PostTrainBench 的名称关系**
   简历不同位置使用了两个名称，面试官很可能抓住这一点。

3. **Agent Loop 的精确机制**
   能够脱离代码画状态图，并解释每个状态、事件、异常和停止条件。

4. **上下文策略的实际算法**
   不能只回答“做摘要和 Recall”，需要说明触发条件、保留规则、失败模式和恢复路径。

5. **多 Agent 的真实收益**
   为什么委派、如何控制预算、如何合并结果，以及什么时候不应该使用多 Agent。

6. **“从零设计”的边界**
   哪些是自研机制，哪些依赖模型 API、MCP、Docker 或 Benchmark Harness。

7. **缺少消融实验的结论边界**
   只能证明整体配置的效果，不能声称某个组件单独贡献了某个提升。

## 十三、Agent 相关八股

这一部分不再局限于简历中的具体实现，主要检查候选人是否具备完整、准确的 Agent 基础知识，能否解释常见技术方案的原理、边界和工程代价。

### 1. Agent 基础概念

1. 什么是 LLM Agent？它与普通聊天机器人有什么区别？
2. Agent、Workflow、Copilot 和 RPA 的区别是什么？
3. 一个最小 Agent 系统由哪些核心组件构成？
4. Agent Loop 中 Observation、Thought、Action 分别代表什么？
5. Agent 的环境、状态、动作空间和反馈信号分别是什么？
6. 什么是 Agent 的自主性？自主性越高是否一定越好？
7. 确定性工作流与模型驱动的动态决策分别适合什么场景？
8. 为什么 Agent 通常比单次 LLM 调用更不稳定？
9. Agent 的能力上限主要由模型、工具还是运行时决定？
10. 如何判断一个业务问题是否真的需要 Agent？
11. Agent 完成任务与模型生成了最终文本有什么区别？
12. Agent 系统最常见的失败模式有哪些？

### 2. 模型交互与提示词

1. System Prompt、Developer Prompt 和 User Prompt 分别承担什么职责？
2. 提示词中的指令、上下文、示例和输出约束应该如何组织？
3. Zero-shot、Few-shot 和动态示例选择有什么区别？
4. Temperature、Top-p 和最大输出 Token 会如何影响 Agent？
5. 为什么低 Temperature 也不能保证 Agent 行为完全确定？
6. 什么是结构化输出？它与要求模型返回 JSON 有什么区别？
7. JSON Schema 能解决哪些问题，不能解决哪些问题？
