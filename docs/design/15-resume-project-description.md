# Simple Long Horizon Agent｜核心开发者

**技术栈：** Python、LLM Agent、Context Engineering、Tool Calling、MCP、Docker、
OpenAI / Anthropic API

**项目简介：** 面向代码修复、终端操作等复杂场景的长周期 Agent 系统，使模型能够
持续读取项目、修改代码、执行命令和验证结果，并根据真实环境反馈迭代修正。

- 设计多轮任务执行链路：模型根据用户目标、历史操作和工具反馈判断下一步，在需要
  补充信息、修改文件或验证结果时调用相应工具；执行结果统一写回任务状态，驱动模型
  继续决策，并通过测试或环境 Verifier 区分“模型声称完成”和“任务实际完成”。
- 解决长任务中的上下文膨胀与能力扩展问题：完整保存模型响应、工具调用和执行结果，
  在接近上下文窗口限制时压缩冗长输出和早期对话，并支持按需找回原始信息；同时设计
  Skill 渐进式加载机制，启动时仅提供技能名称和用途，任务明确命中后再加载操作说明
  与附属资源，通过项目级、用户级和内置级覆盖控制能力范围与上下文开销。
- 设计复杂任务拆分与协作流程：主 Agent 将代码检索、问题定位和局部分析等相对独立的
  工作交给子 Agent，并结合 Planner-Executor 和 Goal Loop 持续推进；子任务结果作为
  工具反馈返回主流程，由主 Agent 统一整合结论、控制写操作，并根据外部检查结果决定
  继续修正或停止。
- 实现服务器重启后的长任务恢复：持久化任务进度、运行事件和隔离工作区引用，由新
  Worker 自动扫描未完成任务并从最近 Checkpoint 继续；通过租约和 fencing token 保证
  同一任务只有一个有效执行者，在文件可能已经修改但工具结果尚未确认时先核对最终
  状态，无法确认则阻断任务，避免重复执行副作用。
- 建设运行观测与评测链路：增量记录模型输入输出、工具执行、Skill 使用版本、异常、
  Token、成本、停止原因和恢复决策；批量评测时保留失败及缺失任务并交由官方 Scorer
  判断结果，接入 SWE-bench Pro 和 Terminal-Bench 2.1，项目公开结果分别达到
  **63.20%** 和 **77.53%**，较对应公开 Baseline 高 **4.10** 和 **12.83 个百分点**。

## 精简版本

### Simple Long Horizon Agent｜核心开发者

- 设计 Python 长周期 Agent Runtime，以显式 Agent Loop 和 Provider-neutral
  数据协议统一模型调用、工具反馈和停止控制，使模型根据真实执行结果持续修正，并由
  测试或环境 Verifier 判断任务是否完成。
- 分离完整运行历史与模型活跃上下文，压缩冗长工具输出和早期对话并支持按需 Recall；
  设计 Skill 渐进式加载及项目级、用户级、内置级覆盖，控制能力范围和上下文开销。
- 实现主 Agent 与子 Agent 的任务拆分和结果汇总，在统一 Runtime 上编排
  Planner-Executor 与 Goal Loop，由主流程控制写操作并根据外部检查继续或停止。
- 基于 Checkpoint、运行事件、Worker 租约和工具副作用核对实现服务器重启后的任务
  接管，保证同一任务只有一个有效执行者，并避免中断后重复修改。
- 建设运行轨迹与评测链路，记录模型、工具、Skill、Token、成本和恢复决策；接入
  SWE-bench Pro、Terminal-Bench 2.1，项目公开结果分别达到 **63.20%** 和
  **77.53%**。
